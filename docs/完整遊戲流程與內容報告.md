## 1. 專案定位與範圍

Outpost Control 是一款雙語、第一人稱 3D 月球前哨站教育遊戲。玩家以坐在控制台前的太空任務人員身分操作場景；主流程由 NOVA 陪同玩家認識環境、閱讀教材、完成課堂實作、回答問題，再進行整合任務。主要對象設定為兒童與初學者，文字以生活例子引入概念，並在教材中區分觀察、推論和遊戲模擬。

目前程式把「課程敘事」和「基地營運模擬」並行處理：課程規定下一個學習目標；實際設備操作則改變基地資源或任務狀態。部分課程學習實作本身會花費資源、消耗當日一次命令，或解鎖進度。因此遊戲同時有知識學習、操作練習和資源取捨三層。

**空間範圍需要先說清楚：**玩家在正式控制艙仍以座位為中心，不能自由走動或在艙內步行探索。迎賓室有受限的前後移動；進入工程／維修、通訊、觀測和教材時，程式以獨立 3D 場景、相機定位或艙間轉場呈現不同操作區。README 也明確說明，控制艙的科學、維修及後方區域是同一房間中的工作區，不是可自由漫遊的獨立地圖。

本專案不是 NASA 官方產品、認證訓練器或可用於真實任務的計算工具。程式中的資源數值、基地點位、訊號序列、軌道路徑、故障和結果多屬遊戲規則或教學模擬；教材用 NASA 公開科學內容作背景，並明確提醒不能把陰影直接當作水冰證據。

## 2. 遊戲流程總覽

```text
遊戲大廳／星空基地
  → NOVA 開場自我介紹與月球基地邀請
  → 3D 迎賓訓練室（視角／方向鍵或 WASD／按鈕／旋鈕／開關／教材／縮放／艙門）
  → 第一課教材：打造探測器
  → 控制艙實作：組裝三個探測器零件
  → 教材反思與三題測驗
  → 第二課選址與能源 → 第三課飛行與軌道 → 第四課通訊
  → 第五課科學觀測 → 第六課故障維修
  → 終章整合任務（回收水、觀測、警報應變）
  → 學習紀錄、任務回顧／結業紀念內容
```

六課的程式 ID 依序為 `assembly`、`plan`、`flight`、`signal`、`explore`、`repair`；終章為 `finale`。每一課通常按此節奏推進：

1. NOVA 介紹任務情境與本課目標。
2. 玩家前往桌上的訓練筆記／教材場景。
3. 讀三頁雙語教材；頁面上先做預測，有指定課程還要在翻頁前辨認線索。
4. 回控制艙親自操作相應設備或任務場景。
5. 完成操作後回到紙本學習區，完成反思活動。
6. 回答三道題；答錯會保留題目並顯示提示／解釋，可再作答。
7. 完成該課後進入下一課；程式將閱讀頁、作答、操作紀錄和課程索引寫入本機儲存。

這不代表所有內容都完全脫離點選題型：教材頁面、預測、反思及正式測驗中仍有選擇題，部分操作是配對或序列記憶。較具身體操作感的環節包括 3D 零件安裝、基地棋子拖動、軌道環對準、天線旋鈕、訊號按鍵、觀測瞄準與線路修復。

## 3. 開場與 NOVA 迎賓教學

### 3.1 大廳場景

大廳由 `LobbyScene.ts` 建構，包含本機生成的星空與棲居地畫面。玩家按 **Begin Adventure／開始冒險** 後進入遊戲；開場可跳過。網頁音訊須在使用者互動後才啟動，以符合瀏覽器音訊限制。

大廳中的開場動畫不是一張單獨插圖：`Game.ts` 控制相機在約 8.5 秒內緩慢靠近場景，另有可跳過的開場流程。初次迎賓進入 3D 空間後，NOVA 會在約 5.5 秒時換第二句台詞，約 12.5 秒結束介紹段並顯示迎賓室第一步。啟用減少動態效果時會停用小幅相機擺動。

### 3.2 NOVA 開場台詞（繁中／英文）

`Game.ts` 目前寫入的兩句開場介紹：

- 「你好，小小太空人！我是 NOVA，你的太空訓練夥伴。」  
  “Hello, junior astronaut! I’m NOVA, your space training companion.”
- 「歡迎來到月球基地。別擔心，我會陪你一起學習、探索，完成每一項任務！」  
  “Welcome to our lunar base. I’ll be right here as we learn, explore and complete each mission together!”

之後迎賓步驟會補充：「嗨！我是 NOVA！歡迎來到太空訓練基地。移動視角看看四周，可以用方向鍵或 WASD 移動！」等操作提示。這是程式直接呼叫 NOVA 說話，不是旁白錄音；NOVA 以程式模型、表情和口型／說話狀態動畫呈現。

### 3.3 3D 迎賓室的操作流程（狀態 0–6）

由 `WelcomeRoom.ts` 建立房間及實體命中目標，`Game.ts` 的 `setWelcomeStep`、`handleWelcomeClick` 和 `updateIntro` 推進步驟。程式記錄狀態 0–6：狀態 0 是初始移動教學，步驟 1–6 是六項互動；透過 `localStorage` 保存目前迎賓進度，完成後設完成旗標。

| 步驟 | 玩家看到／要做的事 | NOVA 繁中提示 | 程式實際反應 |
|---|---|---|---|
| 0 | 房間全景、控制桌與亮起目標；學習看四周、移動位置 | 「嗨！我是 NOVA！歡迎來到太空訓練基地。移動視角看看四周，可以用方向鍵或 WASD 移動！」 | 方向鍵／WASD 與觸控導覽條可移動迎賓視點；前後移動有限制，並避免相機進入訓練桌占用範圍。 |
| 1 | 找到發亮的實體按鈕，先點一次選取／靠近，再點一次操作 | 「看到亮起的按鈕嗎？點它靠近，再按一次。」 | 第一次點擊進入設備特寫，第二次按下按鈕、播放操作聲並轉至下一步。 |
| 2 | 找到實體旋鈕並抓住拖動 | 「現在點亮起的旋鈕靠近，然後按住拖曳。」 | 進特寫後可拖動旋鈕；拖動值變化足夠才算完成。完成後可進下一步。若只點擊，NOVA 會說：「按住旋鈕並拖動，看看刻度改變。」 |
| 3 | 操作撥動開關 | 「接著點亮起的開關靠近，再點一下。」 | 兩段式選取後切換開關，播放切換音效。 |
| 4 | 找訓練筆記並打開 | 「很棒！點亮起的筆記靠近，再點一次。」 | 選取書本後可進入教材；這一步是開啟教材入口，不等同完成第一課。 |
| 5 | 練習縮放 | 「試試滾輪、雙指縮放，或畫面上的縮放按鈕。」 | 滾輪／捏合／加減按鈕調整鏡頭；鏡頭縮放依設定開關。步驟完成後到艙門。 |
| 6 | 找到艙門並離開迎賓室 | 「你準備好了！點亮起的艙門靠近，再點一次出發！」 | 門動畫、門聲、短暫離艙轉場後進主控制艙；清除目前步驟存檔並標記完成。 |

手機與窄畫面在設定迎賓步驟目標時會自動調整座椅朝向，讓目標比較容易進入視野。桌機則可自己轉動視角。玩家需先選取、再操作重要物件，降低單次點擊同時觸發選取與操作的機率。

### 3.4 另一種「迎賓練習」介面

程式另有 `WelcomeFlow.ts`：這是一個 HTML 對話卡片式的五步輔助練習，包含 NOVA 頭像、進度 1/5、跳過與重播台詞、練習按鈕、設備特寫示意、訓練筆記與課程地圖。它說明課程有六課與最後挑戰，並提供「開始第一課」入口。

這個卡片流程與前述 `Game.ts` 中的 3D 迎賓房間是兩個不同程式模組；卡片的練習設備是示範 UI，不應描述成另一個完整實體 3D 教學場景。實際部署會由主流程是否呼叫 `WelcomeFlow` 決定其可見性。報告以 `Game.ts` 的 3D 迎賓步驟作主要開場流程，以免把兩種機制混成同一個房間。

卡片流程的五句 NOVA 台詞（繁中）：

1. 「嗨！我是 NOVA。我們要一起幫月球基地準備任務；我會陪你一步步練習。」
2. 「先練習看看！請點亮起的設備模型，看看它會做什麼。」
3. 「你找到了！這是練習用的設備畫面。現在請按返回。」
4. 「太好了！再打開訓練筆記，看看我們接下來的旅程。」
5. 「這是我們的任務地圖。六堂課和最後挑戰都完成後，就可以回顧旅程！」

### 3.5 NOVA 角色與字幕呈現

`Companion.ts` 建立程式化 3D 機器人，具有漂浮、手臂動作、眨眼及說話狀態。對話文字為即時字幕／文字呈現，不是預錄真人配音。`Game.ts` 會讓 NOVA 朝向相機，並可依目前目標調整所在位置。`SpeechTimeline.ts`、`DialogueState.ts` 協助排定和避免重複推送某些提示。

## 4. 主控制艙、HUD 與操作模式

### 4.1 場景與畫面分區

`ConsoleRoom.ts` 程式化建立艙體、工作桌、物理控制器、螢幕、燈光與 3D 點擊命中區。`ConsoleScreens.ts` 在螢幕 Canvas 上繪製任務、遙測、地圖、教學清單等內容；螢幕不是獨立 HTML 網頁。場景常見顏色為深藍／青灰、金屬灰與暖色提示，但不同控制器仍有狀態燈與教材插圖顏色。

主畫面周邊包括設定入口、鏡頭放大／縮小等 HUD 元件、底部 NOVA 對話／教練提示，以及控制艙裡的實體螢幕和控制器。控制艙以座椅為中心轉動觀看；鍵盤方向鍵／A、D 和觸控導覽條可協助移動視點。README 描述桌機視角使用右鍵拖曳旋轉、R 重設正面、Esc 離開特寫；不同控制方式須以當前 `Game.ts` 及輸入系統行為為準。

### 4.2 主要工作區與實際控制

以下列出目前由 `MissionEngine.ts`、`Game.ts`、`ConsoleRoom.ts` 及各專用場景串接的功能。畫面上的 UI 不必全部同時顯示；部分功能會由任務螢幕入口切換。

| 工作區／功能 | 玩家操作 | 遊戲狀態／回饋 |
|---|---|---|
| 月球選址 `plan` | 拖曳棲居地棋子，在三個教學點中選位置，放開確認 | 日常電力／水資源需求及簡化科學獎勵不同；有地形、日照／任務比較模式；三個點位是遊戲案例，不是真實測量。 |
| 電力 `power` | 點設備選取，再抓滑桿拖曳 | 在水與電間作遊戲內取捨，資源改變；手勢須是拖動才視為對應課堂動作。 |
| 太陽能／探測器準備 `craft` | 拖曳推進桿／相關控制 | 檢查飛行器準備度；後續飛行課必須完成規劃、飛行器和通訊前置條件。 |
| 通訊 `comms` | 控制艙螢幕開啟通訊場景；調天線方向 | 專用通訊房間轉盤約至 80 可對準，之後記憶四燈順序並傳送；遊戲內訊號序列是虛構練習。 |
| 導航 `navigate` | 在軌道／路線控制器拖動標記 | 軌道配對練習可拖金色環與冰藍環對準，可能影響遊戲內後續燃料消耗；不是實際軌道計算。 |
| 科學 `science` | 拖動觀測儀旋鈕調強度／瞄準方向，對準地形目標後掃描 | 觀測結果與資料為模擬；需先移動觀測參數並命中圓形凹陷區才可提交。 |
| 分析 | 拖動分析標記比較合成樣本 | 結果用於教學分析，不是 NASA 儀器輸出。 |
| 水回收 `recycle` | 按下實體控制器 | 水與電資源狀態依遊戲規則改變；終章指定任務之一。 |
| 食物生長 `grow` | 啟用種植設備 | 增加食物但使用其他資源；資源不足時需優先處理。 |
| 時間／一天推進 `advance` | 點時間控制器，或拖動快進旋鈕至 100 後確認；有快速推進模式 | 每日命令、消耗資源、事件和基地變化。快速時鐘遇事件停止等待選擇；不能把遊戲鐘視為真實任務時間。 |
| 暫停 `pause` | 操作切換開關 | 停止／恢復遊戲時鐘。 |
| 避難 `shelter` | 點開透明安全蓋，再操作避難桿 | 事件應變；觸發後依遊戲規則影響人員／資源狀態。 |
| 繼續工作 `continue` | 警報期間選擇繼續 | 在事件情境中作取捨；資源條件可能限制。 |
| 工程組裝 `assembly` | 中央螢幕選 ASSEMBLE，將三個 3D 零件拖到各自接口，完成後啟動 | 一次任務中可領取一次遊戲獎勵；README 記錄耗 4 電力、增加 10 遮蔽。 |
| 線路維修 `repair` | 左側螢幕選 REPAIR，把三條插頭線配到相應接口，啟動檢查 | README 記錄耗 3 水並恢復 12 電力；是簡化遊戲規則。 |

系統包含一次命令／模擬日鎖定、操作冷卻、資源前置條件、事件處理與結束任務狀態。這些用來讓玩家看到資源間關係，而非重現真實月球基地規格。

### 4.3 3D 目標引導

`TargetMarker.ts` 在真正的世界座標建立琥珀色定位標記，標記上方有懸浮符號和短虛線引線，按相機方向轉向並可呼吸／上下微動；程式還提供 marker 的目標 ID、可見狀態和位置快照。`ConsoleRoom` 會提供教學目標，`Game.ts` 依課程與下一個可用動作選擇目標。

螢幕外目標另由 `Game.ts` 的 `updateTargetDirection()` 投影到螢幕邊界附近形成方向提示。要精確描述箭頭造型、遮擋時行為、跨機型視覺效果，仍應實際看最終瀏覽器版本；不能只憑存在 `TargetMarker` 類別就宣稱所有狀況均通過裝置驗收。

### 4.4 設定、文字和音訊 UI

`SettingsPanel.ts`、`TextSystem.ts`、CSS 定義設定、語言、文字大小、鏡頭縮放、減少動態效果和復位視角等操作。相機放大與文字放大是分開控制；場景螢幕、教材 Canvas、標籤或字幕的細節與實際 DPR／畫布更新策略以 `TextSystem` 為準。這份報告不推論達到特定 WCAG 認證。

音樂和效果由 `AudioDirector.ts`／`AudioSystem.ts` 以 Web Audio 合成，使用者首次互動才啟動。README 說明有分開的音樂、音效和 NOVA 聲音音量；同時有艙內低音量氣流／嗡鳴、機械聲、操作提示音、成功／錯誤音與課程音樂主題。沒有錄製真人配音、外部歌曲或付費音效服務。NOVA 的語音是文字對話加電子合成音節／提示音，不是完整自然語音旁白。

## 5. 教材區、閱讀流程與正式測驗

### 5.1 訓練筆記與紙本互動

`QuizRoom.ts`、`ReadingPanel.ts` 和 `TextWrap.ts` 建立單獨的學習房間及紙張顯示。玩家透過 3D 桌面上的訓練筆記進入；相機轉成俯視閱讀視角。紙張可拖曳頁邊翻頁，教材 Canvas 依目前語言與頁碼重畫。可返回主艙，也能繼續上題或下一頁。

每課 `Curriculum.ts` 有三頁正式教材和三題正式測驗。`Journey.ts` 管理目前課程索引、教材頁、預測、反思、回答、錯誤次數、掌握／複習標籤與完成狀態。`LearningActivities.ts` 提供每課的課前預測及課後反思。特定課程在翻過中間頁前需要先完成觀察線索選擇；不是單純任意翻頁。

### 5.2 每課的學習內容完整梳理

**新版生活情境教學卡（`lessonScaffolds`）**會把每課內容再整理成問題、概念、生活比喻、預測和操作後反思。它是正式教材之外的引導／補充層；實際呈現依 `QuizRoom.ts` 當下狀態而定，不能把 scaffold 文案與三頁教材誤認成同一頁。

| 課程 | NOVA／教學問題 | 科學概念與生活比喻 | 動手前預測 → 動手後反思 |
|---|---|---|---|

#### 第一課：打造探測器（`assembly`）

- **目標：**認識探索任務，說明設備如何合作。
- **教材三頁：**「我們為什麼探索？」介紹觀察遠方世界如何幫助了解宇宙與地球；「先派機器探險」介紹探測器可先赴人類難以安全到達的地方觀測；「零件分工」說明電源、電腦、天線、儀器分工。
- **預測：**沒有電源，探測器相機可能怎樣？選擇「可能無法工作／不確定／仍可正常工作」。
- **實作：**在工程組裝場景放入太陽能板、水槽／電池與遮蔽等三件零件，拖放到對應接口；不同零件需旋轉／展開／插入到位，啟動後觀察設備檢查動畫。
- **課後反思：**配對哪種裝置有助保護基地人員；正確概念為遮蔽與乘員保護。
- **正式測驗：**探測器為何用於難達地點、天線用途配對、設計→收集資料→分析的探索順序。
- **核心學習：**探測器收集線索，任務需要多種設備合作；電力支援其他設備。
- **NOVA 實作解說：**成功放置太陽能板時解說它把光轉為電能；電池儲存能量幫助設備度過黑暗；天線讓探測器與基地交換訊息。接口不對時說明「接口沒有對準，零件已回到工作台。再試一次！」啟動時說「啟動檢查中，觀察設備的變化。」

#### 第二課：準備任務／基地選址與能源（`plan`）

- **目標：**解釋有限電力及基地位置的取捨。
- **生活例子：**背包遠足：帶得越多越重，也不能忘記水。另一預測例子比較明亮山脊、長期陰影和不確定位置。
- **教材三頁：**太空船電力來源（太陽能電池、電池儲能）；陰影與電池（不是所有航太器都只靠太陽能）；為任務分配電力（優先順序，選址還要看地形與補給）。
- **預測：**太陽能板通常較容易在哪裡接收陽光？
- **實作：**拖動基地棋子至三個月球教學候選點，比較日照、任務補給和遊戲資源效果；再拖動電力滑桿做取捨。點位／數字是教學模擬，不是實際測量。
- **反思：**除了日照，為何還要看其他條件？答案是日照、可能的冰與地形都影響任務；陰影不保證可用水。
- **正式測驗：**為何要管理有限電力、電力不足且急需傳資料時優先通訊、亮山脊與冷暗坑的可靠判斷。
- **NOVA 遊戲提示：**「先點亮起的選址桌，再拖動基地棋子。」、「點亮起的電力設備，再拖動滑桿。」選址教學引導比較，不直接把陰影宣稱為水冰。

#### 第三課：前往太空（`flight`）

- **目標：**認識重力、軌道、飛行規劃。
- **生活比喻：**把球往前丟；重力使它下落。太空中仍有重力，速度與重力共同影響軌道。
- **教材三頁：**太空也有重力；繞行的路線（軌道是運動路徑，不是實體圓環）；改變方向（推進器改變速度／方向但燃料有限，時間與天體位置也重要）。
- **預測：**衛星繞地球時重力還在作用嗎？
- **實作：**檢查飛行器、規劃目的地、通訊準備後操作導航；另有可拖軌道環與月球模型對齊的練習，以環的可視化模型表達軌道路徑。
- **反思：**遊戲的環代表教學模型中的路徑，不是真實空間中的軌道環。
- **正式測驗：**重力如何與速度塑造軌道、改變速度方向時考慮燃料、檢查設備→規劃路線→推進模擬時間。
- **限制：**遊戲路線與燃料成本為簡化遊戲規則，不是實際軌道計算器。
- **NOVA 提示：**「點右側月球模型，再拖動金色軌道環對齊冰藍色圈。」對準成功則說「對準了！下次出發可以省一點燃料。」

#### 第四課：和地球聯絡（`signal`）

- **目標：**理解無線電訊號及遠距延遲。
- **生活比喻：**收音機接收訊號、傳照片／訊息回家；距離遙遠時需要等待。
- **教材三頁：**探測器用天線送照片；無線電波可穿越太空真空（不同於需要介質的聲音）；光速訊號跨越遠距仍需時間，因此要預先安排程序。
- **預測：**沒有空氣，無線電波能穿過太空嗎？
- **實作：**進入通訊工作站，拖旋鈕讓天線接近 80 的教學刻度；觀察四次燈號並按相同順序；重播後再試，最後傳送訊號。
- **反思：**訊息延遲是因為跨越距離需要時間，不是太空沒有空氣造成無線電無法傳播。
- **正式測驗：**遠距延遲原因、天線用途配對、若指令延遲則預先規劃並讓設備執行適當程序。
- **限制：**四鍵序列為虛構記憶遊戲，不是 NASA 實際通訊碼；數據／獎勵為遊戲設定。
- **NOVA 對話：**進房說「來到通訊室，先拖動旋鈕調整天線方向。」對準後「天線已對準！觀察四次亮燈。」；順序不正確「順序不太對，按重播再試。」；還沒觀察「先觀察亮燈，再開始。」；完成「順序正確，按傳送鍵。」；完成提交前「訊號順序正確，準備傳送！」

#### 第五課：當太空科學家（`explore`）

- **目標：**區分觀察、推測與證據。
- **教材三頁：**先記錄看到的地形，再提出成因假說；說明 NASA LRO 月球南極日照圖亮暗代表照明歷史而非水冰直接量測；單一線索不足以確定可用水，需要其他證據。
- **預測：**看到暗區是否能確定有冰？
- **實作：**在觀測室拖動旋鈕調強度、移動瞄準圈並掃描右側圓形凹陷；調整方向、比較圖面與模擬訊號。操作值標示為模擬。
- **翻頁線索：**程式設兩個觀察／推論判斷，需選觀察事實而非過度推斷才可繼續。
- **反思：**「哪一句是看到的事實？」正確描述是「圖上有一塊暗區」，而非宣稱有可用水或把遊戲訊號當實測冰量。
- **正式測驗：**若訊號可能表示冰，應收集比較更多證據；區分影像觀察與推論；停止觀測不是合理結論。
- **NOVA 對話：**「歡迎來到觀測室。調整儀器，看看地形模型，再進行掃描。」；未調整則「先調整觀測方向與強度，再掃描。」；目標錯誤時「再觀察一次：把觀測圈移向右側的圓形凹陷。」

#### 第六課：緊急任務／設備維修（`repair`）

- **目標：**先診斷問題，理解各系統互相依賴及維修資源成本。
- **教材三頁：**設備為什麼停了（觀察症狀）；像工程師一樣想（先找共用原因而非隨機換件）；相連系統（修一處可能消耗另一種資源）。
- **預測：**多個設備沒反應，先檢查是否共用電源。
- **實作：**進入維修區，把三條不同用途線路接到正確接口，再啟動檢查。錯配會退回重試；成功後線路連接及資源回饋改變。
- **反思：**修復後要檢查設備有無恢復，而非不驗證就宣布成功。
- **正式測驗：**不同設備同時故障時先看共用電源；確認線路／系統用途；維修後驗證結果。
- **限制：**電路配對及耗水／補電結果為遊戲抽象，不是實際航太維修流程。
- **NOVA 對話：**「歡迎來到維修室！把線路接到相同顏色的接口。」；接口成功「連接正確！完整電路才能把能量傳到設備。」；進入工作區另會介紹「這是維修工作台。」

#### 終章：小小指揮官（`finale`）

- **目標：**整合資源管理、科學證據、乘員照護與突發應變。
- **教材三頁：**「指揮一座小小的家」討論不同基地系統共同運作；「面對突發狀況」處理警報；「回顧這趟旅程」回看學習成果。
- **預測：**電和水有限時，從水、電力或乘員安全中判斷優先項目。
- **必做任務：**水回收、科學觀測、警報時選擇避難／事件應變。`Journey.observe` 會在三項最終任務皆加入後才完成整合動作階段。
- **反思：**一起考慮水、電與乘員，是因為系統互相影響、決定有取捨。
- **正式測驗：**綜合資源與證據，而非只看一個數字；遊戲值不能保證真實任務安全。
- **結尾：**課程結束時 NOVA 說「你完成訓練了！桌上的筆記記得我們一起學過的事。」；任務結束流程另有「任務結束！一起看看我們學到了什麼。」以及進入紀錄時「旅程完成！一起看看我們的任務紀錄。」
- **證書／紀錄：**教材房間含任務紀錄／結業展示路徑；不是 NASA 資格證明。完整證書呈現方式須以 `QuizRoom.ts` 實際生成版本為準。

## 6. NOVA 對話總表：常見情境及變化

NOVA 台詞在 `Game.ts`、`WelcomeFlow.ts`、`Journey.ts`、`LearningActivities.ts` 與 `Curriculum.ts` 分散管理。下表整理目前程式中明確可見的對話文字；同一句可在多個事件重現。英文 UI 有對應英文台詞；下面以繁中原文為主，逐課固定教材文字另列於前章。

### 6.1 開始、移動、找目標

- 開場：「你好，小小太空人！我是 NOVA，你的太空訓練夥伴。」
- 抵達月球基地：「歡迎來到月球基地。別擔心，我會陪你一起學習、探索，完成每一項任務！」
- 迎賓室初始提示：「嗨！我是 NOVA！歡迎來到太空訓練基地。移動視角看看四周，可以用方向鍵或 WASD 移動！」
- 目標不對／沒有操作亮起設備：「找找發亮的設備，我們慢慢來。」
- 一般等待提示（第一層）：「需要幫忙嗎？先找亮起來的設備。」
- 一般等待提示（第二層）：「下一步：〔目前課程提示〕」
- 長時間等待（第三層）：「先點亮起的目標，再照操作提示試一步；不急，我會陪你。」
- 點擊控制台動作時若仍在閱讀／答題：「先打開桌上的訓練筆記，一起看看吧！」
- 嘗試操作非本課設備：「我們先完成目前的課程，再來操作這個設備。」
- 一般錯誤或資源不足：「再看看資源和提示，我們可以再試！」
- 成功：「做得好！看看基地發生了什麼變化。」
- 遊戲補給成功：「訓練補給到了！這是遊戲練習用的補給，來繼續任務。」（明確說明是遊戲補給。）

### 6.2 教材、預測、測驗情境

- 進入閱讀：「先來看看桌上的教材，準備好再一起動手！」
- 進入測驗：「我們來想一題！點桌上的訓練筆記，繼續剛才的題目。」
- 每題開始：「輪到你思考了，我會在旁邊陪你。」
- 翻頁前未完成本頁選擇：「先在紙上完成這一頁的選擇，我們再翻頁。」
- 完成三頁並準備操作：「讀完了！現在換我們動手試試。」
- 答錯：「我們再想想，看看紙上的解釋。」
- 答對：「你找到線索了！看看解析，再繼續吧。」
- 下一題：「想想下一個問題，我陪你。」
- 完成一課：「我們完成這一課了！翻開下一課，一起看看新任務。」
- 預測／教材房的不同狀態會依 `DialogueState` 的 `reading`、`quiz`、`wait` 等 trigger 決定，避免打斷更高優先級的台詞。

### 6.4 特定房間操作台詞

**通訊：**

- 進房：「來到通訊室，先拖動旋鈕調整天線方向。」
- 角度偏離：「把旋鈕調到 80 附近，讓天線對準。」
- 尚未校準就嘗試傳送：「先調整天線方向。」
- 還沒觀察燈號就開始：「先觀察亮燈，再開始。」
- 順序錯誤：「順序不太對，按重播再試。」
- 順序完成：「順序正確，按傳送鍵。」或「訊號順序正確，準備傳送！」
- 需要重播時，玩家可按重播鍵；程式重新播放四燈。

**科學觀測：**

- 進房：「歡迎來到觀測室。調整儀器，看看地形模型，再進行掃描。」
- 還未調整：「先調整觀測方向與強度，再掃描。」
- 沒對準：「再觀察一次：把觀測圈移向右側的圓形凹陷。」
- 掃描後回顧：「觀測完成！看到的線索還不是結論，我們需要比較更多證據。」

**工程與維修：**

- 組裝房：「歡迎來到工程組裝室！把零件拖到對應接口，完成後按啟動鍵。」
- 維修房：「歡迎來到維修室！把線路接到相同顏色的接口。」

- 啟動檢查：「啟動檢查中，觀察設備的變化。」
- 未完成所有步驟：「先完成接口，再展開太陽能板、下推電池並旋轉天線。」
- 往另一工作室：「穿過連接通道，一起到另一間工作室。」
- 抵達後：「這是探測器組裝工作台。」／「這是維修工作台。」

**任務結果口語回饋（`showActionResult`）：**

- 選址後：依選擇點名地點及其取捨，並提醒「這些是遊戲模擬條件，請比較取捨。」
- 導航後：「路線選好了。較遠的路程需要更多模擬燃料；真實軌道還要考慮更多因素。」
- 科學觀測後：「觀測完成！看到的線索還不是結論，我們需要比較更多證據。」
- 通訊後：「訊號送出了！無線電波需要時間走過距離，所以地球的指令不會瞬間抵達。」
- 水回收後：「回收水需要電力，請一起查看水和電的變化。」
- 避難後：「避難可減少部分風險，也會消耗基地電力。」
- 其他動作使用共通說法：「觀察設備和資源的變化，再回顧剛才的選擇。」

### 6.5 結束、獎勵與任務紀錄

- 最終任務完成：「任務結束！一起看看我們學到了什麼。」

## 7. 任務狀態、進度儲存與結業紀錄

`Journey.ts` 是課程狀態機。主要 phase 有 `reading`、`operation`、`reflection`、`quiz`、`review`、`completed`。每題答對後要先讀解析、確認後才能進下一題；答錯會計錯誤和標記需複習的概念。

本機儲存 key 包含：

- `outpost-learning-journey-v2`：課程索引、閱讀頁、預測、活動選擇、回答、反思、作答次數與完成紀錄。
- `outpost-mission-progress-v2`：基地資源、模擬任務和工作坊／訊號紀錄等。
- `outpost-dialogue-events-v1`：已播報過、具有穩定事件 ID 的對話，避免重複。
- `outpost-welcome-3d-step`／`outpost-welcome-3d-v1`：3D 迎賓步驟／完成旗標。
- 其他 tour／設定紀錄：導覽完成、語言、聲音、縮放等依專案其他模組處理。

若瀏覽器儲存不可用，遊戲仍可在目前工作階段遊玩；重載後是否保留則依存檔是否成功。損壞或版本不符的存檔會走復原／舊版本遷移路徑，不應假設所有舊資料都完整。

任務結束除了課程完成狀態，也會更新完成次數、最佳健康值、點數／連續天數等遊戲紀錄並顯示 debrief。README 說明任務紀錄會總結資源餘裕、科學資料和決策取捨。它們是遊戲內紀錄，不能證明玩家已掌握課程或取得真實資格。

## 9. 科學來源與模擬界線

教材提及的科學概念包括：探測器遠端觀測、能源儲存、重力與軌道、無線電波可在真空傳播、訊號延遲、月球南極照明差異、陰影不等於已證實有可用水，以及設備系統相依。月球照明圖在 README 標註為 NASA／GSFC／Arizona State University 的 LRO 資料來源。

程式和 README 特別排除以下誤讀：

- 日照圖不是水冰含量圖。
- 陰影、暗區或一個掃描訊號不能單獨證明有可用水。
- 遊戲中的地形、強度百分比、資源消耗、訊號序列和任務獎勵不能用於規劃真實任務。
- 遊戲不是 NASA 產品、NASA 認證訓練器、地表劑量量測、乘員安全預測或飛行軌道計算器。

NASA 資料整合相關程式採快照／離線備援思路；README 當前說明快照刻意為空，遊戲採用離線教育案例，因此不能宣稱目前所有關卡都在讀即時 NASA API。若要對外發布數據，應按 `docs/nasa-data-integration.md` 再檢查來源、時間戳、單位、科學詮釋和資料結構。

## 10. 已知差距與驗收邊界

本文件是程式內容報告，不等同遊戲全流程測試報告。以下界線應保留：

1. README 明載沒有玩家自由步行或地圖漫遊；正式艙內的「不同區域」不等於可自由探索的多房間基地。
2. 組裝和維修是有 3D 模型、拖曳／配對／檢查回饋的教學活動；它們不是全尺寸工程模擬，安裝錯誤也由遊戲規則判定。
3. 六課仍有大量紙本文字與選擇題。互動雖包含拖曳、觀測和排序，尚不能描述成完全以自由實驗取代問答。
4. `WelcomeFlow.ts` 的五步 HTML 卡片和 `Game.ts` 的 3D 迎賓房流程分離；實際玩家進入哪一套取決於部署的呼叫路徑，不能把卡片示意畫面當成真實 3D 交互證據。
5. README 指出桌機／平板／手機仍需實機操作驗證。程式存在觸控 CSS、縮放控制和觸控導覽，不等於已在所有 iPad Safari、iPhone Safari、Android Chrome 版本完成測試。
6. 文字縮放與 DPR 的可讀性應以實際不同解析度目視檢查；不能只由 `TextSystem` 類別存在推定所有文字已達 200% 不裁切。
7. 報告未宣稱已從序章玩到終章完成完整 QA，也未宣稱所有設備操作均已跨裝置驗證。
8. 結業紀念內容是遊戲紀錄／紀念品，不代表 NASA 認證或正式學習資格。

## 12. 一頁版結論

目前遊戲的完整學習旅程是「大廳抵達 → NOVA 3D 迎賓 → 讀教材與先猜 → 進行一項對應實體設備的操作 → 反思 → 三題有解析的測驗 → 下一課 → 回收水、科學觀測、警報應變的終章 → 任務紀錄」。NOVA 以雙語字幕與程式化角色陪同，在初次介紹、等待、設備導引、答錯／答對、房間操作、資源警告和完成時提供條件式回應。

程式已包含可追溯的課程文本、引導台詞、場景與互動模組；但報告也清楚記錄：玩家並非自由走遍全基地，課程仍有紙本文字與選擇題，數值和多種裝置結果屬遊戲模擬，且桌機、平板和手機的最終實機驗收仍需另行完成。這些差異是理解目前作品內容的重要部分。

**NASA 資料狀態：**本輪嘗試從環境連線 NASA DONKI API 失敗，且沒有設定 `NASA_API_KEY`。`public/data/nasa-event-snapshot.json` 仍是明確標記的空快照，遊戲使用內建教育情境。DONKI 目前沒有改變遊戲事件情境；不要描述成已導入即時或歷史太空天氣。課程中使用的 NASA LRO 月球南極日照圖片可見於第五課；它呈現日照條件，不能當成水量圖。

**驗收紀錄：**`npm run build` 通過。Playwright 桌機與手機 Chromium 覆蓋迎賓開始／略過、文字版返回同一 3D 步驟、手機閱讀、200% 字體與來源面板。瀏覽器測試不是實際 Safari／Android 實機驗收；未完成全課程無間斷通關、兒童／老師可用性測試，也未提交 NASA Space Apps 專案。
