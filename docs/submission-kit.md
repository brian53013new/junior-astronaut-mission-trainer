# Space Apps presentation draft

Draft content only. It is not published to a NASA Project Tab. Outpost Control is an independent educational project, not a NASA product, endorsed product, certified trainer, mission planner, radiation forecast or safety tool.

## Project Tab copy (English)

**Title**

Outpost Control: A Data-Evidence Mission for Junior Astronauts

**Short description**

Outpost Control is a bilingual 3D learning game in which children assemble a probe, compare lunar site evidence, manage a simulated outpost, align a communications antenna, inspect lunar imagery, and diagnose a system fault with NOVA.

**Problem and approach**

Young learners often see space exploration as a finished picture rather than a series of evidence-based engineering decisions. Outpost Control turns selected public NASA reference material and a user-supplied data package into a short mission-table activity: read a source card, perform a 3D task, observe a game-state consequence, and save a local learning record.

**Data and evidence**

The checked-in package contains user-supplied DONKI source responses, five NASA Images API records, and three LOLA RDR representative samples. Local checks confirm the supplied hashes, schemas and derived calculations; this development run did not repeat the source HTTP requests. LOLA slope values are sparse-point estimates, not an official LOLA slope field. BVAD Table 4-20 and the 1.624 m/s² lunar gravity reference support educational calculations. PIA13720 is a separate NASA Science Photojournal static image, not an Images API result.

**Limits**

Game resources, mission outcomes, signal delays and scoring are educational models. They do not estimate radiation dose, assess crew health, select a safe lunar site, or calculate an actual trajectory. NASA does not sponsor or endorse the project.

**Access and rights**

The current preview is private. A public release and project-wide license are pending rights-holder confirmation. No learner names, birth dates, addresses, faces, recorded voices or other direct identifiers are collected by the game.

## Seven-slide deck outline

1. **The challenge:** let children see the evidence behind lunar-outpost decisions; show the Mission Table.
2. **One short loop:** NOVA's question → NASA source/evidence card → a 3D action → a visible simulated resource/evidence result.
3. **Six turns:** assemble, choose a site, compare gravity/resources, communicate, observe, repair and decide.
4. **What the data does:** LOLA topography changes the educational site comparison; lunar gravity drives mass-to-weight comparison; DONKI contextualizes a simulated communications priority; Images API results and PIA13720 support evidence classification.
5. **Scientific care:** measured/source fields, derived estimates, static imagery and game mappings are labeled separately; a shadow is not proof of ice.
6. **What was tested:** fresh-storage browser route through certificate, desktop and mobile Chromium emulation, target viewport/text-size checks; physical iPhone/iPad Safari is pending.
7. **Open work and sources:** private preview, NASA references, third-party dependency inventory, pending original-content rights and no-NASA-endorsement statement.

## 30-second demo script

- **0–4 s:** Title, NOVA and mission question: “Where should we build, and what evidence would help us decide?”
- **4–9 s:** Choose one of three LOLA sample points; show coordinates and derived-slope disclosure.
- **9–14 s:** Drag and orient a probe component in the 3D lab; show the simulated readiness/resource change.
- **14–20 s:** Align the antenna, repeat the signal pattern and transmit; identify the DONKI context as a supplied partial snapshot and the effect as a game rule.
- **20–25 s:** Scan the lunar terrain scene and distinguish observed evidence from inference; state that illumination does not measure ice.
- **25–30 s:** Show recorded choices and certificate; close with “independent educational simulation; not a NASA product.”

## 60–90-second expanded demo script

1. Introduce the challenge and child-facing goal (0–8 s).
2. Show how a source card opens provenance and limitations (8–18 s).
3. Compare LOLA samples and choose a site without inferring unmeasured illumination, water or safety (18–30 s).
4. Assemble/activate the probe and show the simulated status change (30–42 s).
5. Align and transmit through the 3D communications station, then show the event-context label and educational-only effect (42–55 s).
6. Adjust the observatory and scan; sort evidence, inference and unknowns (55–68 s).
7. Diagnose/repair, choose finale priorities, and show the locally saved record/certificate (68–82 s).
8. Display source/rights status and the independent-project disclaimer (82–90 s).

No recorded child voice, face, name, birthday, address or other identifying information should appear in the recording.
